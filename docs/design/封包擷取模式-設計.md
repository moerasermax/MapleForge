# 封包擷取模式（Packet Capture）— 設計定案 v1

> 2026-06-01。經 4 輪設計圓桌（提案→收斂→紅隊→簽核），Codex/Sonnet/Kiro/agy **一致簽核**。

## 1. 策略：純 A（擷取加密流 + 離線解密）；B 保留給硬骨頭
- **A**：windower 只 hook winsock，dump 加密原始流 + 未加密握手；解密交離線 C# 工具用我們已驗證的 cipher。穩、不依賴客戶端內部佈局、Themida 改版不易斷。
- **為何純 A 已足夠**：握手 `getHello` 是 server **未加密**送、就在 winsock recv 流裡 → IV 本來就擷取得到，**不需要為拿 IV 而 hook 客戶端**。
- **B（之後）** 只用在真正的硬骨頭：server→client 協定逆向（handler 定位、重放、記憶體快照）。見 §6。

## 2. 擷取層（windower, C++）— 主責 Codex
- **Hook**：`ws2_32` 的 `connect/WSAConnect`、`send/WSASend`、`recv/WSARecv`、`closesocket`，用 **inline detour**（涵蓋 `GetProcAddress` 動態取址，比 IAT 穩）。
- **注入時機（必須早於握手）**：**預設走 suspended-CreateProcess 注入**（先注入裝 hook 再 Resume，保證從握手 byte 0 開始錄）；DllMain 早掛當快速路徑；若偵測首包非握手樣式/缺 IV → 標記不可解 + 自動重啟。
  - ⚠️ Themida 對 suspended 注入可能較敏感（vs SetWindowsHookEx）；實作時驗證是否被擋，被擋則回退 DllMain 早掛 + 重連策略。
- **封包邊界重組**：TCP ≠ maple 封包邊界。**每連線、每方向各自 byte buffer**，按 `stream_offset` 依 `[4B header→len→payload]` 重組，**只在完整包遞進記錄**。漏 1 byte→IV 全歪→偵測訊號＝長度超界/解密後長度校驗連敗→隔離壞段 + 有限掃描重同步。
- **overlapped/WSARecv**：pending 表 key=`(socket, OVERLAPPED*, dir, submit_id)`，記 submit/complete 雙序，完成（`WSAGetOverlappedResult`）才補實際 bytes；未完成前禁重用 key。
- **部分成功/狀態碼**：處理 send/recv 部分成功、`WSA_IO_PENDING`、0-byte、錯誤碼，避免重組位移錯亂。
- **分檔**：每連線一檔 `{pid}_{ts}_{ip}_{port}_{sock}.ndjson`（多實例天然隔離）。
- **開關**：旗標檔/env 啟用，預設關。**安全 fallback：任何 hook 失敗都呼叫原函式，絕不弄掛 client。**

## 3. 擷取格式（NDJSON）
- 首行 session：`{"type":"session","ver":1,"conn_id":"...","remote":"ip:port","ts_start":...,"hello_raw":"hex"}`
- 每包：`{"type":"pkt","seq":N,"dir":"c2s|s2c","ts_qpc_ns":...,"raw_hex":"...","hash":"sha256(canonical(seq+dir+ts+raw))"}`
- 檔尾：`{"type":"end","total":N,"merkle_root":"..."}`（行 hash 的 Merkle root）
- **canonical 序列化**：欄位順序、編碼、時間精度固定，確保 hash 可重算驗證。

## 4. 解碼層（C# `Tools/PacketDecoder`）— 主責 Sonnet
- **重用** `Adapters.V113.Crypto`（`V113CipherFactory`/`MapleAesOfb`），**不複製、不進 server**。
- 從 `session.hello_raw` 解析雙向 IV + maple version；依 `seq` 嚴格順序重播 IV、逐包解密。
- `Decode(ReadOnlySpan<byte> raw, IV, CipherState) → PacketFrame`；**`CipherState` 必須是不可變 value-type snapshot**（避免並行測試互相污染）。
- decoded fixture schema：`{seq, dir, opcode, len, plain_hex, fields?, quirk?, verifier, verified_at, confidence}`

## 5. 正確性 gate（驗證）— 主責 Kiro
1. **雙軌（僅 client→server 有 ground truth）**：server 已解密 log vs 離線解密 → **位元級一致**。
2. **IV 鏈連續**：整段 session IV 從握手到結束連續，斷鏈 → 棄用該 fixture。
3. **結構自證**：解出的 length/opcode 必須合理（排除明顯錯誤）。
4. **多 session 一致**：相同操作多次擷取，opcode 序列須一致。
5. **人工抽驗**：隨機 5 包手解比對，通過才升級黃金測試。
- **鐵則**：server→client 無 ground truth、信心僅 ~70-80%（統計規律、無密碼學保證）→ **未經人工確認的 s2c fixture 一律標 `unverified`，禁止升黃金測試**。fixture 帶 `verifier(auto/human)/verified_at/confidence` 供追溯與降級。
- **防 garbage-in 變權威**：fixture 升黃金前須過上述 gate + 人工核簽。

## 6. server→client 協定逆向（B，之後才做）— 主責 agy/Codex
- **先錄後沙盒重放**（不即時篡改 client，安全可重現）。
- **單欄位變異控制組** + 虛擬時脈 + 狀態快照，崩潰則重置快照重跑 ≥3 次（乾淨歸因，排除非決定性干擾）。
- **handler 定位用簽章 pattern**（找 dispatch table 基底）+ RVA + API 呼叫鏈回溯，**非絕對 VA**（Themida ASLR/混淆會讓 VA 失效）。
- **開源 Java（v95/v117）僅作結構參考**；核心欄位須用 **TMS v113 特有常數/字串強校驗**（版本漂移會解出「看似合理其實錯」）。
- agy 首期前置交付：**v113 opcode 對照表 + 結構定義**（JSON：`Direction/Opcode(hex)/Name/structure`；來源＝v113 主程式分派表逆向 + 動態側寫，開源僅對照），讓 PacketDecoder 上線即能標 opcode。

## 7. 北極星守則（版本抽象不滲漏）— 主責 Sonnet
- **`Adapters.V113` 擁有**：opcode 數字、位元組佈局、加解密、欄位映射。
- **`Core` 只見 domain event**（例：`PinballSpinRequest{slotId,bet}`），**不出現 opcode 數字**。
- 範例切法：`Adapters.V113/Handlers/PinballHandler.cs`（`0x??`→event）；`Core/Game/PinballService.cs`（邏輯，零 opcode）。
- **機器可驗判準**：**Core 單元測試 import 零 `V113` namespace**；做不到＝滲漏。
- 逆向知識經 **fixture/Tools** 傳遞，**不把 hook 邏輯搬進 server**。fixture = 回歸基線，**非設計真相**（設計真相在 domain model）；客戶端怪癖打 `quirk` 標籤（相容但不擴展），避免變成換版本的包袱。

## 8. 模組邊界（`Tools/`）
- `PacketDecoder`（純解碼、無 IO、核心、可單測）｜`Capture`（採集）｜`Replay`（讀 fixture 送 socket）｜`Analysis`（opcode 對照/統計，可選）
- 規則：各子模組獨立可測、**不互相 import**；PacketDecoder 是核心，其餘是它的使用者。

## 9. MVP 第一刀（先打通，不碰硬骨頭）
目標：**擷取一次真實登入封包 → 離線解密 → 位元級斷言**（純 client→server，有 ground truth）。
1. `Tools/Capture` 最薄擷取 → `tests/fixtures/raw/login_c2s.*`
2. `PacketDecoder.Decode(...)` 呼叫現有 `V113CipherFactory`/`MapleAesOfb`
3. `tests/fixtures/golden/login_handshake.json`（opcode+欄位逐字）→ L2 黃金測試斷言每欄位
- **完成判準**：`dotnet test` 綠燈 + `Core` 專案 build 確認**無 `V113` using**。

## 10. 圓桌記錄
- R1 提案：四方皆選 A 為主。
- R2 收斂：純 A 已足夠（握手未加密）；B 改保留給硬骨頭；格式收斂 NDJSON；解碼放 Tools 重用 cipher。
- R3 紅隊：揭露 server→client 無 ground truth（→結構自證+多session+人工抽驗）、TCP≠封包邊界（→buffer 重組）、注入時序（→suspended）、Themida ASLR（→簽章 pattern）、北極星滲漏（→Core 零 V113 import 判準）、fixture 怪癖（→quirk 標籤）。
