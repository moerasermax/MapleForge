## ✅ 結果與結論

- **Give Fame 行為已移植**：同圖目標、不可自己加、等級 15、每日一次、同目標 30 天、mode 0/1 對應 -1/+1、成功後 giver 收成功封包、target 收 `UPDATE_STATS(Fame)` 與被加人氣通知。Core/Application 不含 v113 opcode；封包 layout 留在 `Adapters.V113`。
- **測試結果**：
  - `dotnet test tests\Maple.Application.Tests\Maple.Application.Tests.csproj --filter Fame --no-restore`：通過 6/6。
  - `dotnet test tests\Maple.Adapters.V113.Tests\Maple.Adapters.V113.Tests.csproj --filter Fame --no-restore`：通過 4/4。
  - `dotnet build src\Maple.Host.Login\Maple.Host.Login.csproj --no-restore`：0 warning / 0 error。
- **效能結論（相對舊 JDK8+MySQL）**：
  - 最可能大幅改善：checkpoint/logout/storage 類完整持久化，推估 3x-10x+，因舊服 `saveToDB` 是多表大量 `DELETE/INSERT/UPDATE`，新服目前是角色/帳號/公會文件聚合。
  - 大多接近或小幅改善：移動、一般聊天、party/buddy/chat，同圖 fanout 仍是主成本；慢 client 隔離因 outbound queue 較舊服穩。
  - 戰鬥在目前簡化版可能較快；完整補齊 buff/公式/反作弊後，保守估計 1.1x-1.8x，不應預期穩定 2x。
  - 可能變慢：BCrypt login、未 cache 的 MapData 載入、Jint 每對話 engine 成本、Mongo full document replace 對小型 buddy/guild/cash mutation。
- **後續效能優化優先序**：MapData cache、Mongo delta update/write-behind、field actor/per-field object id、fanout/AOI 或 batching、Guild/Party 鎖粒度、Jint script warmup/engine strategy。
