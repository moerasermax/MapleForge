## 🎯 目標（執行前先寫死，過程不偷改）

對照 Java `InterServerHandler`/`MapleClient.disconnect()` 的 `World.Family.setFamilyMemberOnline`，
補上 MapleForge 家族系統完全缺失的登入/登出線上狀態同步（P005/P006 已對隊伍系統做過同一類修補，
P011 已修過 Family 的 DI 註冊問題，但登入/登出串接仍是空白）。完成判準：玩家登入後，其他家族成員
查族譜（`GetFamilyPedigree`）能看到該玩家為線上且頻道正確；玩家斷線後，其他成員查族譜看到該玩家
變回離線（channel=-1）；單元測試覆蓋兩個方向。

## 📋 背景與假設

- Java 來源：
  - 登入：`InterServerHandler.java:267`：`World.Family.setFamilyMemberOnline(player.getMFC(), true, c.getChannel())`
  - 斷線：`MapleClient.java:804`（`disconnect()` 內 `if (fid > 0)` 分支）：
    `World.Family.setFamilyMemberOnline(chrf, false, -1)`
  - 兩者都在對應的既有 Guild 呼叫（`World.Guild.setGuildMemberOnline`）正下方/正上方各一行，MapleForge
    的 Guild 版本（`V113GuildOperationHandler.OnPlayerLoggedInAsync`/`OnPlayerLoggedOutAsync`）P013 前
    已確認正確接線，但同一批次的 Family 對應版本完全沒做。
- MapleForge 現況：`FamilyService` 的「線上狀態」不是獨立欄位，而是用 `_onlinePlayers` 這個
  `Dictionary<characterId, (Player, channel)>` 的成員關係表示（`Register`/`Unregister`），
  `GetFamilyPedigree`/`GetFamilyInfo` 等查詢時即時用 `_onlinePlayers.TryGetValue` 判斷。但
  `_families.Register(player)` 過去只散落在**每一個家族操作 handler 內部**（邀請/接受/查詢/加成…），
  從未在玩家登入時呼叫；`_families.Unregister` 在整個專案是零呼叫者（grep 確認）。實務後果：
  - 一個從未觸碰過任何家族功能的成員登入後，其他成員查族譜看到的永遠是「離線」，直到該玩家自己
    觸發某個家族 opcode 才會被動更新——與 Java「登入當下就同步」不符。
  - 玩家斷線後，`_onlinePlayers` 字典項目永遠不會被移除，族譜會一直顯示該玩家在線，直到 process
    重啟。
- 修法：在 `V113FamilyHandler` 新增 `NotifyLogin(Player, int channel)`／`NotifyDisconnect(Player)`
  兩個薄包裝（分別呼叫 `_families.Register`/`Unregister`），比照 Party/Guild/Buddy 的
  `NotifyLoginAsync`/`OnPlayerLoggedInAsync`／`OnPlayerLoggedOutAsync` 命名慣例（這兩個是同步方法，
  不需要 async，因為底層 `FamilyService.Register`/`Unregister` 本身就是同步的記憶體操作，沒有 I/O）。
  在 `V113ChannelConnectionHandler.cs` 登入區塊（緊接 `_guildOperationHandler.OnPlayerLoggedInAsync`
  之後）與登出通知區塊（與 P013/P014 同一段 best-effort 區塊）各掛一行呼叫。
- 範圍邊界：只補「登入/登出時的線上狀態同步」這一格，不動任何家族功能本身的邏輯（邀請/加成/親等
  計算等）。

## ✅ 結果與結論

- 這次是「掃描 Java 同一段程式碼裡緊鄰的多個系統呼叫，逐一核對 MapleForge 是否都有對應實作」的
  技巧首次系統性運用（過去 P013/P014 是從「斷線清理總表」找缺口，這次是從「登入流程總表」找），
  兩個方向互補，值得都固化成後續排查的標準動作。
- `FamilyService` 用「dictionary 成員關係」而非「顯式 IsOnline 欄位」表示線上狀態，這個設計本身
  沒問題，但代價是很容易被忽略——沒有一個欄位名稱會在 code review 或 grep 時主動跳出來提示
  「這裡需要在登入/登出時维护」。這類「狀態藏在集合成員關係裡」的設計，未來新增子系統時要特別
  注意在需求文件/程式碼註解裡標注清楚。
