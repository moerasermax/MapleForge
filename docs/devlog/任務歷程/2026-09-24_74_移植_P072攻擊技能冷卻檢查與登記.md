## 📋 背景與查證

- Java `PlayerHandler.closeRangeAttack`（約 679-690 行）、`rangedAttack`（約 830-847 行）、`MagicDamage`
  （約 985-996 行）三處同款冷卻區塊，都在「技能種類檢查（ATTACK_TYPE_ERROR）」之後、廣播/傷害/彈藥消耗之前：
  `effect.getCooldown() > 0` → `skillisCooling(attack.skill)` 則 `enableActions` + return，否則
  `skillCooldown(attack.skill, cooldown)` + `addCooldown(attack.skill, …)`。
- 技能等級查詢走 `GameConstants.getLinkedSkill`（21110007/8→21110002、21120009/10→21120002、4321001→4321000），
  冷卻鍵則是客戶端送來的原技能 ID `attack.skill`。
- Java 在 `effect == null`（未學該技能）時整次攻擊 return——MapleForge 攻擊路徑目前沒有這個閘門，屬另一個
  獨立缺口（會影響所有攻擊，風險較高），本 P 不動，只讓冷卻判斷在查不到效果時回 `NotApplicable`。
- GM 無敵狀態跳過冷卻為 GM 工具，不移植。
