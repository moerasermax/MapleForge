## 🎯 目標（執行前先寫死，過程不偷改）

P041 收尾記下：Java `UseTeleRock`/`UseCashItem` 任意門分支的判斷式除了 VipRock 場地
限制，還有 MapleLand 排除、已註冊地圖清單驗證、大陸比對、`EventInstance` 排除。這次
接續處理其中最小、無需新基礎設施的一項：MapleLand 排除。完成判準：玩家目前在楓之島
或（傳送石情境）目標地圖是楓之島時，兩個現金道具流程都要擋下傳送。

## 📋 背景與查證

- Java `UseTeleRock`（現金傳送石地圖模式）：`if (!c.getPlayer().inMapleLand() && !MapConstants.isMapleLand(map)) { ... } else { dropMessage("無法在楓之島使用。") }`——目前地圖或目標地圖任一是楓之島就整段跳過。
- Java `UseCashItem` 任意門分支：`if (c.getPlayer().inMapleLand()) { dropMessage; break; }`——只檢查玩家目前地圖（目標地圖已被前置的 `mapId <= 2000000` 檢查排除，楓之島地圖 ID 遠小於此門檻，等於間接涵蓋）。
- `MapConstants.isMapleLand(int mapid) => mapid < 1010004`。MapleForge 已有等價私有靜態方法 `V113ChannelConnectionHandler.IsMapleLand`（用於 `CanEnterCashShopFromMap`），確認公式正確；本次在 `V113UseCashItemHandler` 內新增同名獨立私有方法（同檔案內小型純函式，未強行抽共用抽象）。
- Java 兩處都是 `dropMessage` 提示訊息 + 略過，MapleForge 既有慣例（P041、既有 `AnyDoorTicket` 的 `mapId <= 2_000_000` 分支）是略過訊息本體、只送 `enableActions()`（`EnableActionsOnly()`），本次延續此慣例。
