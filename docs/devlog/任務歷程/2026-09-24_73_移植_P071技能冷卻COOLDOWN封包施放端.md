SPECIAL_MOVE 施放有冷卻的技能成功時，伺服器比照 Java 送 `COOLDOWN`（0xE3，`int skillId + short seconds`）
給施放者，讓客戶端技能圖示顯示冷卻；冷卻中被拒絕時比照 Java 回 `enableActions` 解鎖客戶端。

## 📋 背景與查證

- Java `PlayerHandler.SpecialMove`（約 578-591 行）：`effect.getCooldown() > 0` 時先 `skillisCooling`
  → 冷卻中送 `enableActions()` 並 return；否則（`skillid != 槍神.海盜船`）送
  `skillCooldown(skillid, effect.getCooldown())` + `addCooldown`。GM 無敵狀態跳過冷卻屬 GM 工具，不移植。
- Java `MaplePacketCreator.skillCooldown`：`writeShort(COOLDOWN) + writeInt(sid) + writeShort(time)`；
  `send.properties`：`COOLDOWN = 0xE3`。
- 海盜船的冷卻在 Java 是船被打爆時才由 `MapleCharacter`（2148 行）登記，施放時不登記。
- MapleForge 現況：`SkillService.Cast` 已有 `SkillIsCooling`/`AddSkillCooldown`（只在套用成功時登記），
  但整個 Adapter 沒有 COOLDOWN 封包，冷卻中被拒也什麼都不回。
- 刻意差異：Java 是先登記冷卻再套用效果（MP 不足也會進冷卻），MapleForge 維持「套用成功才登記」，
  封包跟著登記走，兩者狀態一致。
