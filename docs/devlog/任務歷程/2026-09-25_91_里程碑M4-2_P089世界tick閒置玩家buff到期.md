## 🎯 目標（執行前先寫死，過程不偷改）

P082 查證時發現：MapleForge buff 只在「玩家送任何封包」時才檢查到期，完全閒置的玩家 buff 永遠不會到期，P081-088 綁在 buff 上的
召喚獸與時空門也會一直留著。Java 每個 buff 由 `BuffTimer` 排程在到期時 `cancelEffect`。把到期檢查加進世界 tick 逐玩家處理，並把
buff 結束副作用（召喚獸/門）抽成共用類別。完成判準：測試綠燈、build 0/0、全測試無退化。

## 📋 背景與查證

- Java `MapleStatEffect.applyBuffEffect` → `BuffTimer.getInstance().schedule(new CancelEffectAction(...), duration)`：到期即 `cancelEffect`，與封包活動無關。
- MapleForge：`SendExpiredBuffCancelsAsync` 只在每個收到的封包前執行；世界 tick（3 秒）已有逐玩家入口（P073）。
- 副作用原本寫在連線 handler 私有方法（P082/P088），tick handler 無法共用 → 抽成 `V113BuffCancellationEffects`（Adapter，依賴 SummonService/DoorService/IMapSessionRegistry）。
