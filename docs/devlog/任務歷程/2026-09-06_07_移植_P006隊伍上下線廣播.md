## 🎯 目標（執行前先寫死，過程不偷改）

P005 收尾時發現的已知缺口：`PartyMember.IsOnline` 從未在登入/登出被更新（永遠 `true`）、
`PartyUpdateKind.LogOnOff` 從未被觸發。對照 Java `InterServerHandler`（登入）+ `MapleClient.
disconnect`（登出，含隊長斷線自動轉移最高等級在線隊友），補上這條線。完成判準：登入時隊伍
其他在線成員收到 LOG_ONOFF 通知（該成員 online=true）；登出時其他在線成員收到 LOG_ONOFF 通知
（online=false）；若離線者是隊長，自動轉移給地圖內等級最高的在線隊友（比照 Java）；單元測試
覆蓋；既有測試不退。

## 📋 背景與假設

- Java 來源：`handling/channel/handler/InterServerHandler.java:222-225`（登入時 `World.Party.
  updateParty(partyId, LOG_ONOFF, new MaplePartyCharacter(player))`）；`client/MapleClient.java:
  776-792`（登出時 `chrp.setOnline(false)` → `updateParty(LOG_ONOFF, chrp)` → 若離線者是隊長，
  在**同地圖**的隊友中挑等級最高者 `updateParty(CHANGE_LEADER_DC, lchr)`）。
- 這與 P005 的 `NotifyMapEntryAsync`（`SILENT_UPDATE`，每次進地圖都觸發，含初次登入與每次換圖）
  是兩個不同事件：本次的 `LOG_ONOFF` 只在「頻道登入」與「登出/斷線」各觸發一次，不隨換圖重複。
- Java 隊長轉移只從「同地圖」的隊友中選——但 MapleForge 目前沒有可靠取得「隊友目前所在地圖」的
  即時來源（`PartyMember.MapId` 由 P005 的 SilentUpdate 保持新鮮，可以用；但嚴格「同地圖」比對
  在單機多頻道/多地圖情境下有其必要性，故沿用 `PartyMember.MapId` 做同地圖過濾，符合 Java 語意）。
- `PartyService.ChangeLeader(leaderId, newLeaderId, disconnected: true)` 已存在，直接重用。

## ✅ 結果與結論

- 完整補齊隊伍系統的線上狀態同步：P005（SILENT_UPDATE，每次進圖）+ P006（LOG_ONOFF，登入/登出 +
  隊長斷線轉移）合起來讓 `PartyMember` 快照不再是「建立/加入當下一次性」的過時資料。
- 隊長斷線自動轉移的「同地圖」限制是本次容易漏掉的細節——若不限制地圖，可能把隊長轉移給一個等級
  更高但根本不在附近、玩家看不到後續互動脈絡的隊友；寫了專門測試區分「同地圖較低等級」vs「不同
  地圖較高等級」來鎖死這個語意，避免之後不小心簡化掉。
