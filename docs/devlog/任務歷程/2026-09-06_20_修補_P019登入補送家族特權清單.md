繼續 P016/P017/P018 的零呼叫者封包掃描候選清單，處理 `V113FamilyPackets.FamilyPrivilegeList`。
完成判準：玩家登入時無條件收到家族特權/花費表封包（不限是否已加入家族，對照 Java 行為）；單元
測試覆蓋封包版型（opcode/entry count/每筆 entry 欄位）。

## 📋 背景與假設

- Java 來源：`InterServerHandler.java:277`（登入流程）：`c.sendPacket(FamilyPacket.getFamilyData());`——
  這行在 `if (player.getFamilyId() > 0) { ... }` 區塊**之外**，對所有玩家無條件執行。
  `FamilyPacket.getFamilyData()`（`tools/packet/FamilyPacket.java:36`）寫的是
  `FAMILY_PRIVILEGE_LIST(0x5C)` opcode + `MapleFamilyBuff.getBuffEntry()` 全表（type/repCost/count=1/
  name/desc），與 MapleForge `V113FamilyPackets.FamilyPrivilegeList()`（opcode 0x5C 對應
  `SendFamilyPrivilegeList`，序列化 `FamilyBuff.All`）逐欄位一致——這代表 MapleForge 早就正確
  移植了這個封包的**格式**，只是沒有接上登入流程的**呼叫點**。
- **本次修正 P016 的一個誤判**：P016 任務歷程曾記錄「登入時 `FamilyPacket.getFamilyInfo` 自身
  資訊封包是否要補送...本次判斷為低優先級，非行為缺陷」，把 `getFamilyData()`（特權清單，靜態表，
  給**所有**玩家）誤認成 `getFamilyInfo(player)`（個人家族資訊，僅家族成員需要）混為一談，因而
  錯誤地降低優先級跳過。這次重新拆分兩者：`getFamilyInfo(player)` 確實依賴玩家是否有家族、且
  client 開 UI 時會主動要（`REQUEST_FAMILY`/`OPEN_FAMILY` opcode 已有 handler），維持不動；
  `getFamilyData()`／`FamilyPrivilegeList` 是**與家族成員身分無關**的靜態表、Java 對所有人無條件
  送出，屬於真缺口，本次修補。
- 範圍邊界：只補這一個封包的登入時序，不動 `FamilyResult`（同檔案另一個零呼叫者候選，Java 對應
  方法名稱查無直接匹配，需要更多研判，留給下一個 phase）。
