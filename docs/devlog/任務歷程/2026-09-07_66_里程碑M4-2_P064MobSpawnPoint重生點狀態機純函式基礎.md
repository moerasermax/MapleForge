## 🎯 目標（執行前先寫死，過程不偷改）

延續 M4-2 里程碑，掉落物過期（P061-063）走完一輪三步驟劇本後，這次開始第二個切片：怪物
重生。沿用同一套「先立資料模型/純函式（不變行為）」的第一步——新增 `MobSpawnPoint`，對照
Java `server.life.SpawnPoint` 的 `shouldSpawn()`/死亡監聽重排邏輯，純粹是一個可獨立測試的
狀態機，**刻意不接任何排程器、不接任何真正生怪/殺怪的行為**。

## 📋 背景與查證

- 對照 Java `MapleMap.respawn(force)`：對每個地圖的 `monsterSpawn`（重生點清單）逐一檢查
  `spawnPoint.shouldSpawn()`，通過就 `spawnPoint.spawnMonster(map)`，直到達到
  `monsterSpawn.size() * 3 - spawnedMonstersOnMap.get()` 這個地圖級生怪上限。
- 追到 `server.life.SpawnPoint.shouldSpawn()`：
  - `mobTime < 0` 永不重生（固定裝飾用途，非戰鬥怪）。
  - `(mobTime != 0 || immobile)` 為真時，這個點最多同時存在 1 隻自己生出的怪（`immobile =
    !monster.getStats().getMobile()`——怪物模板本身不會走動）。
  - 否則（`mobTime == 0` 且怪物會走動）最多同時 2 隻。
  - 還沒到 `nextPossibleSpawn` 也不能生。
  - 怪物死亡時（`MonsterListener.monsterKilled`）：`mobTime > 0` 才把 `nextPossibleSpawn`
    延後 `mobTime` 秒，否則立刻可重生；同時歸還這個點的並發額度。
- 查證 MapleForge 現有資料：`MapService.LoadMonsters` 早就把 WZ `mobTime` 欄位解析進
  `MapMonster.MobTime`（`Cy` 屬性的既有註解甚至寫著「保留給後續重生/落地修正」），
  `MobStats.Mobile` 也早就存在——這代表底層資料早就備妥，只是完全沒有任何程式碼真正讀取
  `MobTime` 去做重生判斷，是典型的「資料就位、邏輯沒接」缺口，跟 P056/P058 那類缺口同一種
  形狀，只是規模更大（需要整套重生管線才會真的動起來）。

## 🔧 實作內容

- **`Maple.Core`**（新檔 `World/MobSpawnPoint.cs`）：`MobSpawnPoint` 持有一份 `MapMonster`
  靜態定義 + `Mobile` 旗標 + 執行期狀態（`NextPossibleSpawn`、內部 `_spawnedCount`）：
  - `ShouldSpawn(now)`：逐行對照 Java `shouldSpawn()`。
  - `OnSpawned()`：對照 `spawnedMonsters.incrementAndGet()`。
  - `OnMonsterKilled(now)`：對照 `MonsterListener.monsterKilled`，`MobTime > 0` 才延後
    `TimeSpan.FromSeconds(MobTime)`（WZ 原始值是秒，Java 建構式才轉毫秒，這裡直接用
    `TimeSpan.FromSeconds` 對應），計數額度用 `Math.Max(0, ...)` 保護不會變負數。

## 🧪 測試

- `tests/Maple.Core.Tests/World/MobSpawnPointTests.cs`（新檔）：8 組——`MobTime<0` 永不重生、
  剛建立可立刻生、`MobTime>0` 單點上限 1 隻、`MobTime==0` 且不會走動一樣上限 1 隻（對照 Java
  `immobile` 分支）、`MobTime==0` 且會走動上限 2 隻、殺怪後依 `MobTime` 秒數延後下次重生、
  `MobTime==0` 殺怪後立刻可重生、計數額度歸還不會變負數。
- `dotnet build` 0 warning/0 error；全 8 個測試專案 1044 passed / 1 skipped（P063 收案基準
  1036 +8：Core 140→148）；Core/Application 禁區 grep clean。

## ✅ 結果與結論

- 跟 P061 一樣，這步**刻意不改變任何現有伺服器行為**——`MobSpawnPoint` 存在且測試通過，但
  沒有任何地方建立它的實例或呼叫它，玩家端完全感受不到差異（怪物被殺掉後依然不會重生）。
- 下一步（P065）：在 `Maple.Application` 層新增「給定 field + 該地圖的重生點清單 + now，
  找出該生的怪並生出來」用例（比照 P062 `ExpireDrops` 的角色），這裡會需要決定
  `spawnedMonstersOnMap`（地圖級生怪計數）要放在哪一層追蹤——初步傾向讓 `FieldInstance`
  自己統計目前場上的 `Mob` 數量（`Objects.OfType<Mob>().Count()`），不用額外開一個計數器
  欄位，減少雙重真相的風險。
- 之後（P066+）：接上排程器（可以重用 P063 `DropExpiryHostedService` 的骨架，或考慮這時候
  才把它重構成通用的 world tick host，讓掉落物過期跟怪物重生共用同一個 `PeriodicTimer`
  迴圈——這個判斷留到真的要動手時再評估）+ 怪物死亡要呼叫 `MobSpawnPoint.OnMonsterKilled`
  的掛勾點（現有的 mob 擊殺流程在 `DropService.OnMobKilled`／中央 dispatcher 的擊殺處理，
  需要先確認怪物物件跟它出生的 spawn point 之間目前有沒有關聯可查）。
