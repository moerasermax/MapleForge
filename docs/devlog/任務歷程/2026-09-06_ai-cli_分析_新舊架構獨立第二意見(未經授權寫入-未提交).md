## ✅ 結果與結論

達成原定評估目標。長期框架與 AI 輔助維護偏向保留 MapleForge；短期營運、固定 v113、既有 Java 熟練度則偏向 Java 漸進重構。收益來自可驗證边界，不是 C# 語言本身。

現行證據：
- Core Guild 純模型與可替換 repository 有真實測試價值；Java MapleGuild 建構子查 SQL、領域操作直接依賴 World/packet，隔離成本較高，但有 CopyOnWriteArrayList/讀寫鎖，不能說完全沒有並行保護。
- Channel handler 仍為中央巨型協調器；約 1996 行直接協調 BBS 刪除、同盟移除、在線角色狀態，業務用例尚未完整收斂在 Application。
- GuildService.cs:113 registry 共用一把 instance gate；188–190 行先改記憶體再寫 DB，外層約 808 行另寫角色，故有部分成功風險。未做故障注入，不宣稱已重現。
- Guild.cs 的 setters/Members 可變；Snapshot 克隆成員有隔離價值，不能推論模型本身有完整不變量保護。
- GuildServiceTests fake 保存原參照，部分封包測試使用被測常數作 expected，無法獨立證明 DB/協定正確。
- Core/IO/PacketReader.ReadMapleString 含 short 長度前綴，Core csproj 註記封包 Big5；零 I/O 不等於完全無 wire 知識。
- P010/P030 是已修接線缺陷；P011 是已修、尚無介面消費者時發現的潛在 DI 影子實例，非已發生事故。
- 設計書 §0.5 已撤回只加 adapter 即跨版本的過強承諾；tracker M4-2/M5-6 尚未完成，不能把編譯或測試數量當完整可營運證据。
