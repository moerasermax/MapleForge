## 🎯 目標（執行前先寫死，過程不偷改）

> 把 v113 的 **NPC 對話（點 NPC→跑腳本→多輪對話）** 移植到 MapleForge 乾淨分層架構，**不照 OdinMS static 風格硬抄、邊做邊重構**（使用者明確要求）。用 Jint 跑既有 2644 個 .js 腳本（相容層），不重寫腳本。
>
> **完成判準（本任務 MVP）**：
> 1. c2s `NPC_TALK(0x33)` → server 查 NPC→啟動該 npcId 的腳本對話；c2s `NPC_TALK_MORE(0x35)` → 解析 (lastMsg, action/mode, selection) → resume 腳本。
> 2. s2c `NPC_TALK(0x13C)` 對話封包建構器（對照 Java getNPCTalk：sendNext/sendNextPrev/sendOk/sendSimple/sendYesNo/sendGetText/sendGetNumber 的 msgType 0/2/3/4 + 按鈕 endBytes），位元組對齊真 Java。
> 3. Jint 引擎跑腳本：對話狀態（script 全域 scope、status 變數）跨封包持續（每 active 對話一個 Engine、綁 session 生命週期）。
> 4. `cm` host 物件提供腳本 API 最小集：sendNext/sendNextPrev/sendOk/sendSimple/sendYesNo/dispose（＋ getJob/getMeso/gainMeso/warp 視範例腳本所需）。
> 5. 分層乾淨：opcode/封包鎖 Adapters.V113；腳本引擎/載入在 Maple.Scripting；對話用例/生命週期在 Application；領域操作（warp/meso）走 Core；**零 V113 滲漏進 Core、不搬 OdinMS static 單例**。
> 6. **build 綠**（使用者指示先不寫單元測試；里程碑後可真客戶端 smoke 點計程車 NPC 驗對話）。

## 📋 背景與假設

> 路線圖①已收官。Java 權威源：`handling/channel/handler/NPCHandler.java`(586行,handleNPCTalk/NPCMoreTalk)、`scripting/NPCConversationManager.java`(2103行,巨無霸 cm API)、`scripting/NPCScriptManager.java`(348行,生命週期)。腳本 `scripts/npc/*.js`(2644個,OdinMS Rhino 風,用 cm.* + #L#l 選單標記)。
> **opcode 定案（送自 send/recv.properties，權威）**：c2s NPC_TALK=0x33 / NPC_TALK_MORE=0x35 / NPC_SHOP=0x36；s2c NPC_TALK=0x13C(2-byte) / NPC_ACTION=0xFC / OPEN_NPC_SHOP=0x13D。
> **getNPCTalk 布局**：[short 0x13C][byte 4][int npcId][byte msgType][byte type][maple-string talk][endBytes]。msgType: 0=ok/next(endBytes=prev/next 旗標2byte) / 2=getText / 3=getNumber(def/min/max/0) / 4=simple 選單 / 7=style。
> **NPC_TALK_MORE 解析**：[byte lastMsg][byte action][依 lastMsg 型別讀 selection(int 或 byte)]；對 cm.action(mode=action, type=lastMsg, selection)。
> 假設：Jint 跑 OdinMS 腳本需相容 shim（importPackage/Java 型別/條件運算）；2644 腳本不重寫。商店(getNPCShop)較大，本 MVP 先做純對話，shop 留下一刀。
