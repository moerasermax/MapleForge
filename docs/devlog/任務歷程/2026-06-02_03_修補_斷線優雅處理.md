## 🎯 目標（執行前先寫死，過程不偷改）

> 客戶端**正常/突然斷線**時，server 不應拋例外並以 `fail:`+stacktrace 記錄；應辨識為正常斷線，記 `info`（或 `debug`）級「連線關閉」訊息後乾淨收尾。
> **完成判準**：headless（或真客戶端）連上後斷線，server log **不再出現 `fail:`+stacktrace**，而是一行乾淨的斷線 info；且既有測試全綠、登入→進圖流程不受影響。

## 📋 背景與假設

- 來源：任務 `2026-06-02_01/02` 觀察到——headless 斷線時 `TcpChannelListener`(TcpChannelListener.cs:64) log `fail:`，stacktrace 指向 `MapleSession.RunAsync`(MapleSession.cs:85) 與 `V113ChannelConnectionHandler.HandleChannelConnectionAsync`(:57/:126)。
- 假設：RunAsync 的讀迴圈在 socket 被對端關閉時拋 IOException/SocketException（或 EOF→某 InvalidDataException），未被分類為「正常斷線」。
- 範圍：Net 層（login + channel listener 都該一致處理）。不改協定。

## 🪜 計畫步驟

- [x] 1. 定位：`MapleSession.RunAsync` 原本只 catch `EndOfStreamException`（乾淨 EOF），但突然斷線（TCP reset）拋 `IOException`/`SocketException` 未被接住 → 冒泡到 `TcpChannelListener.HandleAsync` generic catch 記 `fail:`。body 讀取(:107)更是沒包 try。
- [x] 2. 設計：把整個讀迴圈 I/O 包進 try，用 `when` 過濾 `EndOfStreamException/IOException/SocketException/ObjectDisposedException`→正常斷線記 info+return；真錯誤（解析 bug 等）不在此列，繼續向上拋給 listener 記 Error。
- [x] 3. 改 `MapleSession.RunAsync`（login+channel 兩 listener 都走它，一處修兩邊一致）。
- [x] 4. 測試 29/29 綠（無回歸）；live：headless 進圖後 force-kill → server log 乾淨 `連線關閉` info，`fail:`/stacktrace 計數=0。
