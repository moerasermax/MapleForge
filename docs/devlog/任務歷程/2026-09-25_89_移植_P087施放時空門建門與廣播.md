## 📋 背景與查證

- Java `isMagicDoor()`：`skill && sourceid ∈ {2311002, 8001, 10008001, 20008001, 20018001, 30008001}`。
- Java `applyTo`（746-764 行）：`new MapleDoor(applyto, pos ?? truePosition, sourceid)`；`getTownPortal() != null` → `map.spawnDoor(door)` + 村莊 `spawnDoor(townDoor)`；
  否則 `dropMessage(5, "無法使用時空門，村莊不可容納。")`。
- Java `MapleDoor`：`town = target.getReturnMap()`；`getFreePortal()`：村莊 type 6 portal 依 ID 排序，排除「門主人與本人同隊伍」的門佔用者，取第一個。
- Java `MapleDoor.sendSpawnData(client)`：client 在目標地圖（或主人本人且無隊伍）→ `spawnDoor(ownerId, 村莊? townPortal : targetPos, true)`，
  隊伍成員另送 `partyPortal`，最後 `spawnPortal(town, target, skill, targetPos)`。townDoor 的 target 同為目標地圖，所以村莊裡其他人收不到 spawn data（照 Java）。
- 重複施放：`applyBuffEffect` 的 `cancelEffect` 先關舊門（`sendDestroyData`：`removeDoor(owner, false)` + `spawnPortal(999999999, 999999999)`）。
- MapleForge 封包 builder 與 Java 版型一致；`Door.ObjectId = OwnerId`，門由 `DoorService` 自己保存，不放進 `FieldInstance`（避免與玩家 ObjectId 相撞）。
