## 📋 背景與查證

- Java `ChatHandler.Messenger`：`joinMessenger(id, new MapleMessengerCharacter(chr), name, c.getChannel())`（`c.getChannel()` 1-based）。
- Java `World.Messenger.joinMessenger`：新成員 → 他人 `addMessengerPlayer(from, fromCh, position, fromchannel - 1)`；既有成員 → 新人
  `addMessengerPlayer(chr.getName(), chr, mposition, messengerchar.getChannel() - 1)`。`updateMessenger` 同樣 `fromchannel - 1`。
- MapleForge 資料流：連線 handler 傳 `_options.ChannelIndex + 1`（1-based）→ `MessengerMember.ChannelIndex` 存 1-based；
  `CentralMessengerSessionHook` 回傳 `online.Channel`（登入時登記 `ChannelIndex + 1`，1-based）→ 三個封包 builder 原樣寫出 → 比 Java 大一。
- 既有 `MessengerHandlerTests.Join_OpenExisting…` 用 0/1 當頻道輸入並期望原樣輸出，等於把差一鎖成真相；改成 1-based 輸入、Java 0-based 期望。
